### Safety finding: the resolver must never re-derive context for historical rows

`CONTEXT_ONLY` disagreements are not resolver errors, and acting on them would destroy correct data.

The resolver takes `context` from the node's **current** declared `measurement_context`, which is right at ingest — a node declares what it is doing now. It is wrong for history. N003 is declared `bench` today, so the resolver labels its 2026-05/06 prototype capture `bench`; M5 classified those rows `laboratory` on the platform owner's determination, and M5 is correct.

Consequences, both already enforced:

- The resolver is an **ingest-time** function. It must never be run as a backfill over stored rows.
- The M8 reconciliation is bounded by `m5_n003_boundary < id <= m8_freeze_point`. Every `CONTEXT_ONLY` row sits at or below that boundary and is therefore outside the window by construction.
